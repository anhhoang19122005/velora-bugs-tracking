## Nguyên nhân

`GlobalExceptionHandler` của order-service chuyển exception thành JSON nhưng không ghi log ở bất kỳ nhánh nào. Khi có lỗi 500, cửa sổ service không có stack trace, nên chỉ thấy mã lỗi ở phía client. Identity-service đã có cách làm đúng ở `GlobalExceptionHandler.java:37-47`.

## Thay đổi

File: `services/order-service/src/main/java/vn/edu/iuh/fit/taschen/order/exception/GlobalExceptionHandler.java`

### 1. Dòng 18-19: khai báo logger

```diff
+@Slf4j
 @RestControllerAdvice
 public class GlobalExceptionHandler {
```

Thêm `import lombok.extern.slf4j.Slf4j;`.

**Vì sao:** Lombok `@Slf4j` là cách các lớp khác trong service đang dùng, ví dụ biến `log` trong `OrderServiceImpl`.

### 2. Dòng 21-26: `handleAppException`

```diff
     public ResponseEntity<ErrorResponse> handleAppException(AppException ex, HttpServletRequest request) {
         ErrorCode errorCode = ex.getErrorCode();
+        if (errorCode.status() >= 500) {
+            log.error("[{}] {} at {} - {}", traceId(), errorCode.code(), request.getRequestURI(), ex.getDevMessage(), ex);
+        } else {
+            log.warn("[{}] {} at {} - {}", traceId(), errorCode.code(), request.getRequestURI(), ex.getDevMessage());
+        }
         ErrorResponse body = ErrorResponse.of(errorCode, ex.getMessage(), traceId(), request.getRequestURI());
```

**Vì sao:** cùng định dạng với identity-service nên log các service đọc giống nhau và tìm được theo `traceId`. Lỗi 5xx kèm stack trace. Lỗi 4xx là tình huống bình thường, chỉ ghi `warn`. `getDevMessage()` chứa chi tiết không được gửi cho người dùng, nên ghi vào log là đúng chỗ.

### 3. Dòng 43-47: `handleUnexpected`

```diff
     public ResponseEntity<ErrorResponse> handleUnexpected(Exception ex, HttpServletRequest request) {
+        log.error("[{}] Unhandled {} at {}", traceId(), ex.getClass().getSimpleName(), request.getRequestURI(), ex);
         ErrorResponse body = ErrorResponse.of(ErrorCode.INTERNAL_ERROR, traceId(), request.getRequestURI());
```

**Vì sao:** đây là nhánh quan trọng nhất, mọi lỗi ngoài dự kiến đều qua đây. Bug này đã che nguyên nhân thật của [SF-02](SF-02.md).

## File mới

Không có thêm, dùng chung file test với SF-02. Nếu SF-03 làm trước thì file test được tạo tại đây.

## Kiểm thử lại

- Gây một lỗi 500 trên `POST /api/v1/orders`, cửa sổ `order-service` phải có dòng `error` kèm `traceId` và stack trace.
- `./mvnw.cmd spotless:apply`, `./mvnw.cmd clean verify` trong `order-service`.

## Tuân thủ quy tắc

Java 4 dấu cách, Spotless, theo mẫu có sẵn ở identity-service. API không đổi nên không cần sinh lại contract.
