## Nguyên nhân

Storefront có hai form đăng nhập và cả hai đều phân loại lỗi sai:

- `login/page.tsx:64` coi mọi status 403 là tài khoản chưa xác thực. Ngoài trường hợp đó còn có 403 của gateway (như [SF-01](SF-01.md)), với body rỗng. Người dùng được khuyên xác thực email trong khi lỗi không liên quan.
- Form thả xuống ở header (`AccountMenu.tsx:104-105`) báo mọi lỗi là "Email hoặc mật khẩu không đúng", kể cả tài khoản chưa xác thực và lỗi kết nối.

Identity trả `FORBIDDEN` trong `code` ở body (`AuthServiceImpl.java:109-110`), còn CORS 403 của gateway không có body. Storefront đang bỏ mất trường `code`.

## Thay đổi

### 1. `src/lib/axios/axios.ts`, dòng 5-9

```diff
 export type ApiError = {
   status: number;
   message: string;
+  code?: string;
   errors?: Record<string, string[]>;
 };
```

### 2. `src/lib/axios/http.ts`, dòng 10-13 và 30-34

```diff
 type ErrorResponse = {
   message?: string;
+  code?: string;
   errors?: Record<string, string[]>;
 };
```

```diff
     message: data?.message ?? "Server Error",
+    code: data?.code,
     errors: data?.errors,
```

**Vì sao:** `code` có sẵn trong mọi phản hồi lỗi (`ErrorResponse.java:12`). Đây là thay đổi cộng thêm, các nơi đang dùng `ApiError` không bị ảnh hưởng. [SF-02](../storefront-backend/SF-02.md) cũng sửa các khối này, nếu làm cùng thì gộp lại.

### 3. `src/modules/auth/hooks/use-login.ts`, thêm hàm dùng chung

```ts
export type LoginFailure = "credentials" | "unverified" | "connection";

// Identity's 403 carries a code; a gateway 403 has an empty body and is not about the account.
export const loginFailure = (error: unknown): LoginFailure => {
    const { status, code } = (error ?? {}) as Partial<ApiError>;
    if (status === 403 && code === "FORBIDDEN") return "unverified";
    return status === 401 || status === 400 ? "credentials" : "connection";
};
```

**Vì sao:** hai form dùng chung một quy tắc, nên quy tắc nằm một chỗ cạnh `useLoginMutation`. Lỗi 403 không có mã rơi vào `"connection"`, đúng với bản chất lỗi. Ở bước đăng nhập, `FORBIDDEN` hiện chỉ phát sinh từ `!user.isActive()`.

### 4. `src/app/[locale]/(auth)/login/page.tsx`, dòng 39 và 61-69

Bỏ kiểu `Failure` cục bộ và khối phân loại, thay bằng `setFailure(loginFailure(error))`.

### 5. `src/app/[locale]/(main)/_components/Header/AccountMenu.tsx`, dòng 94-107 và 168-172

Đổi state `failed` thành `failure` kiểu `LoginFailure`, và hiện đúng 3 thông báo như trang `/login`. Thông báo chưa xác thực có link tới `/verify-email`.

**Hạn chế:** `isActive` hiện chỉ mang nghĩa "chưa xác thực". Nếu sau này có khóa tài khoản dùng cùng mã `FORBIDDEN`, backend cần một mã riêng.

## Test

Thêm vào `e2e/api/storefront.spec.ts`, mock bằng `page.route` như các test trong file. Không dùng `e2e/auth.spec.ts`, vì file đó viết cho bản prototype và không khớp trang đăng nhập hiện tại:

- "a 403 without an error code is not reported as an unverified account": mock `/api/v1/auth/login` trả 403 body rỗng, không thấy thông báo chưa xác thực.
- "an unverified account is told so": mock 403 với `{ "code": "FORBIDDEN" }`.
- Hai trường hợp trên chạy cho cả form ở header.
