## Nguyên nhân

Cùng dạng với SF-02: địa chỉ không có ràng buộc ký tự, còn `Order` thì có.

```text
Order.java:54  tên người nhận:  ^[\p{L}\p{M}0-9 ]+$
Order.java:66  địa chỉ giao:    ^[\p{L}\p{M}\p{N}\s,./#-]+$
```

`shippingAddress` được ghép từ số nhà, phường, quận, thành phố (`OrderServiceImpl.java:326-332`). Vì vậy cả 4 trường này đều phải đạt quy tắc, không chỉ tên người nhận.

## Thay đổi

### 1. Backend: hai file DTO địa chỉ

`services/identity-service/.../dto/request/CreateAddressRequest.java` và `UpdateAddressRequest.java`, sửa giống nhau.

Với `recipientName`, dòng 30-32:

```diff
         @NotBlank(message = "Recipient name is required")
         @Size(max = 255, message = "Recipient name must not exceed 255 characters")
+        @Pattern(regexp = "^[\\p{L}\\p{M}0-9 ]+$", message = "Recipient name must not contain special characters")
         String recipientName,
```

Với `addressDetail`, `ward`, `district`, `city`, thêm vào mỗi trường:

```java
        @Pattern(
                regexp = "^[\\p{L}\\p{M}\\p{N}\\s,./#-]+$",
                message = "Address must not contain invalid special characters")
```

**Vì sao:** API là ranh giới tin cậy, form phía trước có thể bị bỏ qua. Dùng đúng biểu thức của `Order.java` để hai nơi không lệch nhau. Chỉ thêm khi tạo và sửa, nên địa chỉ cũ không bị ảnh hưởng cho tới khi chỉnh sửa. Nếu địa chỉ cũ sai, đặt hàng sẽ trả 400 nhờ handler ở [SF-02](SF-02.md).

### 2. Storefront: `src/modules/user-address/schemas/user-address.schema.ts`

Sau dòng 15:

```ts
// The same character sets Order enforces at checkout (Order.java).
const RECIPIENT_NAME = /^[\p{L}\p{M}0-9 ]+$/u;
const ADDRESS_TEXT = /^[\p{L}\p{M}\p{N}\s,./#-]+$/u;
```

Dòng 21 và 26-29:

```diff
-  recipientName: requiredText(255),
+  recipientName: requiredText(255).regex(
+    RECIPIENT_NAME,
+    "profile.page.validation.recipientName",
+  ),
```

```diff
-  addressDetail: requiredText(500),
-  ward: requiredText(255),
-  district: requiredText(255),
-  city: requiredText(255),
+  addressDetail: requiredText(500).regex(ADDRESS_TEXT, "profile.page.validation.addressText"),
+  ward: requiredText(255).regex(ADDRESS_TEXT, "profile.page.validation.addressText"),
+  district: requiredText(255).regex(ADDRESS_TEXT, "profile.page.validation.addressText"),
+  city: requiredText(255).regex(ADDRESS_TEXT, "profile.page.validation.addressText"),
```

**Vì sao:** báo lỗi ngay trên form. Cờ `u` bắt buộc để JavaScript hiểu `\p{L}`. `UpdateUserAddressSchema` dòng 33 dùng chung schema nên tự có quy tắc mới.

## Kiểm thử lại

- Lưu tên `John@#` hoặc số nhà `12 (A)`: form báo lỗi, API trả 400.
- Tên tiếng Việt có dấu và số nhà `12/3A, Lê Lợi` vẫn lưu được.
- Chạy lại [HD Địa chỉ](../../storefront/hd-dia-chi.md) và [HD Đặt hàng](../../storefront/hd-dat-hang.md).
- Backend: `./mvnw.cmd spotless:apply`, `./mvnw.cmd clean verify` trong `identity-service`.
