## Nguyên nhân

Có hai vấn đề độc lập:

1. **Phiên đăng nhập:** `lib/auth/token.ts` giữ cả access token và refresh token trong biến JavaScript. F5 xóa bộ nhớ nên phiên mất. Comment ở `token.ts:1-4` đã ghi nhận hạn chế này.
2. **Giỏ của khách:** `useCart` (`cart.store.ts:263`) không dùng `persist`, nên các dòng hàng chỉ nằm trong bộ nhớ. Store cũ `useCartStore` ở dòng 87 có `persist`, nhưng các màn hình giỏ hàng đọc từ `useCart`.

## Cách backoffice làm và phần áp dụng

Tham chiếu: `taschen-backoffice/packages/core/src/api/` (`auth-cookies.ts`, `auth-service.ts`, `routes/auth-login.ts`, `routes/auth-refresh.ts`, `routes/auth-logout.ts`).

| Điểm | Backoffice | Storefront sau khi sửa |
|---|---|---|
| Nơi giữ token | Cả hai trong cookie httpOnly | Giống |
| Trình duyệt thấy token | Không | Không |
| Tên cookie | Theo từng app | `taschen_storefront_access`, `taschen_storefront_refresh` |
| Hạn cookie | Access theo backend, refresh 30 ngày | Giống |
| Hai request refresh cùng lúc | Dùng chung một lần đổi token | Giống |
| Đăng xuất | Thu hồi nếu được, cookie luôn bị xóa | Giống |
| Refresh bị từ chối | Xóa cookie | Giống, nhưng chỉ với lỗi 4xx |
| Nơi refresh | Middleware, trước khi render | Interceptor 401 có sẵn của axios |
| `path` cookie | `/` | `/api` |
| Ô "Ghi nhớ đăng nhập" | Có | Không, vì form storefront không có ô này |

**Ba điểm khác có chủ đích:**

- **Nơi refresh:** backoffice render dữ liệu ở server nên phải refresh trước khi render. Dữ liệu cá nhân của storefront được tải ở client, interceptor tại `http.ts:125-141` đã xử lý 401 nên không cần thêm middleware.
- **`path` là `/api`:** chỉ proxy đọc cookie này, nên trình duyệt không cần gửi nó kèm request tải trang.
- **Chỉ xóa cookie khi lỗi 4xx:** gateway tạm lỗi (5xx, 502) không có nghĩa là token hỏng, không nên đăng xuất người dùng.

**Vì sao không dùng lại code của backoffice:** đây là hai repo riêng, và storefront đã có một proxy duy nhất. Thêm các route riêng như backoffice sẽ tạo file mới không cần thiết, nên toàn bộ logic nằm trong `route.ts`.

```ts
const ACCESS_COOKIE = "taschen_storefront_access";
const REFRESH_COOKIE = "taschen_storefront_refresh";
// Only this proxy reads them, so page requests do not need to carry them.
const COOKIE_SCOPE = { ...COOKIE_OPTIONS, path: "/api" };

const LOGIN = "v1/auth/login";
const REFRESH = "v1/auth/refresh";
const LOGOUT = "v1/auth/logout";

type Upstream = { status: number; type: string | null; payload: ArrayBuffer };

async function forward(url: string, init: RequestInit): Promise<Upstream> {
  const upstream = await fetch(url, init);
  return {
    status: upstream.status,
    type: upstream.headers.get("content-type"),
    payload: await upstream.arrayBuffer(),
  };
}

// Refresh tokens are single-use: concurrent callers holding the same one share one exchange.
const refreshing = new Map<string, Promise<Upstream>>();

function refreshOnce(
  token: string,
  url: string,
  init: RequestInit,
): Promise<Upstream> {
  const existing = refreshing.get(token);
  if (existing) return existing;
  const attempt = forward(url, init).finally(() => refreshing.delete(token));
  refreshing.set(token, attempt);
  return attempt;
}

function clearSession(response: NextResponse): void {
  for (const name of [ACCESS_COOKIE, REFRESH_COOKIE]) {
    response.cookies.set(name, "", { ...COOKIE_SCOPE, maxAge: 0 });
  }
}

function toBrowser(route: string, upstream: Upstream): NextResponse {
  const { status, type, payload } = upstream;
  const headers = new Headers();
  if (type) headers.set("content-type", type);

  if ((route === LOGIN || route === REFRESH) && status >= 200 && status < 300) {
    const json = JSON.parse(new TextDecoder().decode(payload));
    // A 2FA challenge carries no tokens and passes through without setting a cookie.
    const { accessToken, refreshToken, ...rest } = json.data ?? {};
    const response = new NextResponse(JSON.stringify({ ...json, data: rest }), {
      status,
      headers,
    });
    if (accessToken && refreshToken) {
      response.cookies.set(ACCESS_COOKIE, accessToken, {
        ...COOKIE_SCOPE,
        maxAge: rest.expiresInSeconds ?? COOKIE_ACCESS_TOKEN_MAX_AGE,
      });
      response.cookies.set(REFRESH_COOKIE, refreshToken, {
        ...COOKIE_SCOPE,
        maxAge: COOKIE_REFRESH_TOKEN_MAX_AGE,
      });
    }
    return response;
  }

  const response = new NextResponse(payload, { status, headers });
  // A refused token is spent. A 5xx says nothing about the token, so the session stays.
  if (route === REFRESH && status >= 400 && status < 500) clearSession(response);
  return response;
}
```

**Dòng 44-80, thay hàm `proxy`:**

```ts
async function proxy(
  request: NextRequest,
  context: { params: Promise<{ path: string[] }> },
): Promise<Response> {
  const { path } = await context.params;
  const route = path.join("/");
  const base = await backendBaseUrl();
  const url = `${base}/api/${route}${request.nextUrl.search}`;

  // GET and HEAD carry no body, and fetch rejects one that does.
  const method = request.method;
  let body: Blob | string | undefined =
    method === "GET" || method === "HEAD" ? undefined : await request.blob();
  const headers = forwardedHeaders(request);

  const refreshToken = request.cookies.get(REFRESH_COOKIE)?.value;
  // A visitor with no session: answer here instead of asking the gateway on every page load.
  if (route === REFRESH && !refreshToken) {
    return NextResponse.json(
      { code: "UNAUTHORIZED", message: "No session." },
      { status: 401 },
    );
  }
  if ((route === REFRESH || route === LOGOUT) && refreshToken) {
    body = JSON.stringify({ refreshToken });
    headers.set("content-type", "application/json");
  }

  const init: RequestInit = {
    method,
    headers,
    body,
    // The proxy is a pipe. Whatever caching there is belongs at the ends, not here.
    cache: "no-store",
    redirect: "manual",
  };

  if (route === LOGOUT) {
    // Best effort: leaving the browser signed in after it asked to leave is the worse outcome.
    if (refreshToken) await forward(url, init).catch(() => undefined);
    const response = NextResponse.json({ success: true, data: null });
    clearSession(response);
    return response;
  }

  try {
    const upstream =
      route === REFRESH && refreshToken
        ? await refreshOnce(refreshToken, url, init)
        : await forward(url, init);
    return toBrowser(route, upstream);
  } catch {
    // The gateway is unreachable — both the deployed one and the local fallback. Say so as a
    // gateway error rather than a 500, which would read as this app having failed.
    return NextResponse.json(
      { message: "The backend is not reachable." },
      { status: 502 },
    );
  }
}
```

**Vì sao đặt ở proxy:** mọi lời gọi backend đã đi qua đây, nên không cần file mới và không phải sửa backend. `src/config/cookie.config.ts` có sẵn `httpOnly`, `sameSite: lax` và `secure` ở production.

**Vì sao F5 hết lỗi:** khi access cookie còn hạn, `/users/me` thành công ngay. Khi hết hạn, `/users/me` nhận 401, interceptor gọi refresh, proxy đổi token và ghi cookie mới, rồi interceptor gọi lại.

**Vì sao chống được đua token:** khác với cách lưu access token trong RAM, F5 trong 15 phút không tiêu refresh token. Sau khi hết hạn, các request đồng thời của cùng token dùng chung một lần đổi nhờ `refreshOnce`.

**CSRF:** cookie có `sameSite: lax` nên request POST từ site khác không mang theo cookie. Đây cũng là mức bảo vệ backoffice đang dùng.

## Rủi ro đã biết

- `refreshOnce` nằm trong bộ nhớ của một tiến trình Node, giống backoffice. Khi chạy nhiều instance, hoặc khi một tab gửi token cũ ngay sau lúc tab khác vừa đổi xong, tab đến sau bị từ chối và phiên sẽ kết thúc.
- Giá và tồn kho trong giỏ khách là bản lưu lại, có thể cũ. Khi đăng nhập, `serverLines` sẽ dùng giá của server.
- Người đang đăng nhập lúc triển khai bản này sẽ phải đăng nhập lại một lần.

## Kiểm thử lại

- Đăng nhập, F5: vẫn đăng nhập. DevTools: hai cookie có cờ httpOnly, phản hồi login không có token, request từ trình duyệt không có header `Authorization`.
- Xóa riêng access cookie rồi F5: phiên được khôi phục qua `/auth/refresh`, refresh cookie đổi giá trị.
- Mở nhiều tab rồi F5 cùng lúc sau khi access cookie hết hạn: các tab vẫn đăng nhập.
- Đăng xuất: hai cookie biến mất, F5 vẫn là khách, kể cả khi gateway đang tắt.
- Khách thêm sách, F5: giỏ còn. Đăng nhập: giỏ được gộp, `localStorage` hết dòng hàng.
- Chạy lại luồng 2 và [HD Đăng nhập](../../storefront/hd-dang-nhap.md). `pnpm lint`, `pnpm typecheck`, `pnpm test:e2e e2e/api`.
